# 通用開發規則

> AgentPacks dev-base 規範（claude / codex / opencode 共用）。專案有更具體的規範時以專案為準；
> commit 格式與分支策略不在本檔，見 git-spec 的 `.agent/spec/git.md`、`git-project.md`。

## 程式碼

- 使用有意義的變數與函數命名，避免單字母變數（迴圈索引除外）。
- 每個函數加上簡潔的用途註釋；風格、註解密度跟隨周邊既有程式碼。
- 錯誤處理不可省略，所有外部調用需有 try-catch 或等效機制。
- 禁止 hardcode 密鑰、密碼、API key，一律用環境變數或不進版控的設定檔。
- 不在 session 中用 shell 連續執行超過 10 次 HTTP request（curl、wget…）；需要批量抓取時，產出腳本讓用戶自行執行。

## 檔案搜尋（Windows）

- 搜尋時忽略大小寫差異；首次找不到時換大小寫組合（`README.md` / `readme.md`）再找一次，不要直接回報找不到。
- 讀取或修改檔案前，先確認檔名的實際大小寫。

## API 串接

- 先確認實際回傳的資料結構（讀 API 文件、打 sample request，或請用戶提供範例），不可憑猜測撰寫解析程式碼。
- 特別注意欄位命名差異（例 `data.stocks` vs `data.list`），解析前先驗證。

## 檔案讀取

- 預設信任上次編輯的結果，不重新讀取驗證。
- 用戶說「手動改了 X」「剛 git pull / checkout」「檔案被外部程式改過」時，才重新讀取指定檔案。
- 主動告知需要重新讀取：編輯失敗找不到目標字串、檔案狀態與記憶不符、距上次讀取已很久。

## 任務執行

- **複雜任務先規劃**：涉及架構設計、多檔變更或需求不明確時，先提出計畫與用戶確認再實作。
- **需求複述確認**：要建構工具或功能時，先複述核心需求，區分例如「處理原始資料的掃描器」與「讀取既有結果的檢視器」。
- **不熟悉的專案先探索**：先摸清結構（框架、進入點、關鍵設定檔），回報後再改程式碼。

## 文件

- README.md 保持最新：安裝步驟、啟動方式、環境變數說明（可用 `readme` skill）。

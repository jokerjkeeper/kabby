kabby × Cloudflare Tunnel 部署教學

把 GCP 上的 kabby 安全地暴露到 https://kabby.你的網域.com，免開任何對外 port、TLS 自動、token 當密碼。

這份教學會達成什麼

瀏覽器 / 本機 wepages │ https (443) ▼ ┌──────────────────────┐ │ Cloudflare (TLS 終止) │ └──────────┬───────────┘ │ 加密的出站隧道（GCP 主動連出，無 inbound port） ▼ cloudflared（跑在 GCP） │ http://localhost:3700 ▼ kabby daemon（綁 127.0.0.1，用 AUTH_TOKEN 擋）

重點：GCP 不用開任何 inbound 防火牆，cloudflared 是主動往 Cloudflare 連出去。kabby 只聽 127.0.0.1，唯一入口是通過 Cloudflare 的隧道。

前置需求

  1. 一個 Cloudflare 帳號（免費方案即可）
  2. 一個掛在 Cloudflare 上的網域：在 Cloudflare 後台 Add a site 加入你的網域，再到你的網域註冊商把 nameserver 改成 Cloudflare 提供的兩個 NS，等生效。
  3. 一台能 SSH 進去的 GCP server（Linux，以下以 Debian/Ubuntu 為例）
  4. kabby 已能在該 server 上 npm start 跑起來（聽 127.0.0.1:3700，且 .env 裡設了 AUTH_TOKEN）
沒有網域怎麼辦？ 可以先跳到最後的「快速測試（免網域）」用 TryCloudflare 拿一個臨時網址驗證，確認可行再買網域做正式部署。

A在 Cloudflare 後台建立 Tunnel

  1. 登入 Cloudflare Dashboard → 左側 Zero Trust
  2. Networks → Tunnels → Create a tunnel
  3. 連線器類型選 Cloudflared → 取個名字（例如 kabby）→ Save tunnel
  4. 畫面會給你一段含 token 的安裝指令（依作業系統不同）。先把那串 token 複製起來，下一步會用到。

B在 GCP server 安裝並啟動 cloudflared

SSH 進 GCP，安裝 cloudflared（Debian/Ubuntu 直接抓官方 .deb 最省事）：

curl -L --output cloudflared.deb \
  https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-amd64.deb
sudo dpkg -i cloudflared.deb

接著把後台給你的安裝指令貼上 —— 它會把 cloudflared 裝成開機自啟的 systemd service並連回 Cloudflare：

sudo cloudflared service install <後台給你的TOKEN>

確認服務有跑：

sudo systemctl status cloudflared
# 看 log： sudo journalctl -u cloudflared -f
回後台看連線狀態 回到 Tunnels 頁面，剛建的 tunnel 狀態應該變成 HEALTHY，代表 GCP 的 cloudflared 已連上 Cloudflare。

C設定 Public Hostname（路由到 kabby）

  1. 在該 tunnel 的設定頁 → Public Hostname 分頁 → Add a public hostname
  2. 填寫：
    欄位填什麼
    Subdomainkabby
    Domain選你的網域 → 對外即 kabby.你的網域.com
    Service · TypeHTTP
    Service · URLlocalhost:3700
  3. Save
完成 打開 https://kabby.你的網域.com 就會通到 GCP 上的 kabby，HTTPS 憑證由 Cloudflare 自動處理。WebSocket（kabby 終端串流）Cloudflare Tunnel 預設就支援，不用額外設定。

安全檢查清單

務必設 AUTH_TOKEN kabby 會啟動帶 --dangerously-skip-permissions 的 Claude Code —— 沒設 token 等於把一個可任意執行指令的 shell 開放給所有知道網址的人。.env 一定要設 AUTH_TOKEN。
  • GCP 防火牆不用開 3700（也不用開任何 inbound）—— cloudflared 是 outbound 連出。若先前有開過 3700 的規則，建議移除。
  • kabby 綁 127.0.0.1（預設）→ 只有同機的 cloudflared 連得到。不要設 HOST=0.0.0.0。
  • 產生強 token：node -e "console.log(require('crypto').randomBytes(24).toString('base64url'))"
  • 跨域給本機 wepages 用的話，.env 設 KABBY_ALLOWED_ORIGINS=http://localhost:5002,http://127.0.0.1:5002

讓 kabby 本體常駐

cloudflared 已是 service，但 kabby daemon 也要常駐（不能只靠 SSH session 裡的 npm start，斷線就停）。請見另一份教學把 kabby 設成 systemd service：

docs/deploy-systemd.md

快速測試（免網域、免後台）臨時

想先確認 kabby 經過 https / wss / token 通不通，一行就好（在 GCP 上跑）：

cloudflared tunnel --url http://localhost:3700

它會吐一個隨機網址，例如 https://random-words.trycloudflare.com，立刻可用瀏覽器或 wepages 測試。

只適合臨時測試 每次重啟 cloudflared 網址都會換、且沒有正式 SLA。確認可行後，請走上面 A→C 的正式流程。

本教學對應 kabby 部署前認證強化（token / ws→wss / 綁 localhost / CORS 白名單）。API 細節見 docs/api.md。
